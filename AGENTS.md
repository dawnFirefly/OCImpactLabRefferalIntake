# ReferralReady agent handoff

## Current scope and user decisions

This repository currently contains **a frontend scaffold only**. The user explicitly stopped backend/OCR implementation. Document understanding will use a Claude model in a later task.

- Keep the minimal three-section workspace: PDF list on the left, connected patient-information nodes in the middle, result checklist on the right.
- Use Vue 3 / Nuxt 4 and actual shadcn-vue components. Vue Flow owns graph layout, pan, zoom, and source-to-fact edges.
- Do not add a dashboard, navigation shell, admission workflow, authentication, or a Python backend unless the next user task asks for it.
- Do not implement or install local OCR, Tesseract, PDF text extraction, or image-based extraction. Do not analyze the supplied packets as part of frontend work.
- Do not mistake mock fixtures for analysis. Files attached in the current UI are browser-local and await a future Claude integration.

## Start here

```sh
cd frontend
npm ci
npm run dev
```

Development URL: `http://127.0.0.1:3000`. No backend or API key is required.

Before delivery: `npm run typecheck` and `npm run build` from `frontend/`. For UI changes, render the actual screen and check the relevant interaction. Keep these commands and the README accurate.

## Architecture

- `frontend/app/app.vue`: three panels, graph slots, checklist, review dialog, browser PDF preview.
- `frontend/app/composables/useReviewWorkspace.ts`: session-local attachment and review state.
- `frontend/app/data/demo.ts`: explicitly synthetic fixtures, separate from real packets.
- `frontend/app/types.ts`: the graph/evidence/checklist result contract.
- `frontend/app/services/analysis.ts`: intentionally unimplemented `AnalysisProvider` for a later Claude integration.
- `frontend/app/components/PdfSourceViewer.client.vue`: browser-only PDF.js page rendering and normalized highlight overlay; no text extraction or OCR.
- `frontend/app/lib/demoPdf.ts`: runtime generation of fictional PDFs matching the authored demo anchors. Do not replace these with real packet content.
- `frontend/app/components/ui/`: source-owned shadcn-vue components generated by its CLI.
- `frontend/app/assets/css/main.css`: minimal workspace appearance and responsive layout.
- `docs/claude-integration.md`: future integration boundary and current limitations.

Keep service orchestration outside graph templates. An eventual model response should update the typed workspace rather than introduce a second UI model. Preserve original source values when a coordinator edits extracted information.

## Data and decision semantics

The original R01/R02 packets are external files, not repository fixtures. Do not commit PDFs, screenshots of real packets, extracted packet text, credentials, or patient data. Keep fixtures fictional. Blacked-out data in the challenge examples means redacted for privacy, not missing.

For explicitly requested local packet previews, `scripts/link-demo-pdfs.mjs` creates ignored symlinks and a metadata manifest in `frontend/public/local-demo/`. R01/R02 remain separate referrals. The UI discovers these on mount and offers a switch back to the synthetic flow. Never assign fictional facts/anchors to a real packet. Do not distribute a build containing these local-only assets.

Historical labels supplied by IHH are evaluation outcomes; reasons were not recorded. They must not be used to fabricate rationales or hardcode model decisions. Distinguish evidence found, not found, conflicting, and coordinator-confirmed. A checklist count is not a clinical admission decision.

The challenge's official criteria are linked in `docs/claude-integration.md`. When later implementing rule review, preserve source rule IDs and their stated precedence, including case-by-case decisions and conditional requirements.
